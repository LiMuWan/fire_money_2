# FireMoney 核心业务功能基准

## 1. 产品北极星

FireMoney 当前只验证一条纪律：主板 10cm 主线首板。

用户真正要完成的是：

```text
今日决策 -> 模拟盘指挥单 -> 盘中买卖纪律 -> 晚评复盘 -> 收益/回撤证据
```

首版不保留多战法、旧 demo、旁支交易流或通用交易终端能力。

---

## 2. 三段核心业务线

### 2.1 今日决策

用户问题：

**今天有没有主板 10cm 主线首板机会？如果没有，为什么空仓？**

保留能力：

- 市场温度。
- 主线首板候选。
- 50-800 亿市值带。
- 封板质量、换手质量、主线持续性。
- 硬拦截原因和观察提示。
- 主线或现金的唯一默认路由。

不做成首版主入口：

- 多战法扫描。
- 研究线买入入口。
- 独立消息中心。
- 复杂主题大屏。
- 与主线首板无关的大量指标卡。

### 2.2 模拟盘执行

用户问题：

**候选触发后，模拟盘如何按纪律执行？**

保留能力：

- 只读模拟盘指挥单。
- 真实模拟买入事件。
- 持仓风险和 T+1 卖出纪律。
- 小账户一手约束和仓位上限。
- 结构止损、固定比例止损、正收益锁盈和主升保护。
- 买入/卖出后飞书只推关键动作。

暂缓能力：

- 自动实盘交易。
- 多账户维护。
- 券商 SDK 操作。
- 与当前候选无关的账户总览。

### 2.3 晚评复盘

用户问题：

**今天的样本告诉我什么，收益和回撤质量是否足够？**

保留能力：

- 晚评。
- 成功/失败闭环样本。
- 最近完成样本摘要。
- 止损、锁盈和纪律退出原因。
- 样本数和观察期状态。
- 年度/月度收益、最大回撤、赚撤比和弱年份提示。
- 30/50/100 笔后的策略边界建议。

暂缓能力：

- 大型历史统计中心。
- 泛 AI 实验台。
- 复杂报表导出中心。
- 与主线首板无关的参数海。

## 3. 功能优先级

### P0：必须做好

- MarketDataProvider/AkShare 行情边界。
- 主线首板候选评分。
- ST、退市、新股、非主板、高位、压力近、一字买不到等硬拦截。
- 模拟盘 JSON/SQLite 账本。
- 交易日历和严格 T+1 状态流转。
- 本地/服务器调度器按早评、盘中、晚评推进主线闭环，并防止同日重复触发。
- 每天最多 1 笔。
- 小账户一手制。
- 完成交易样本归档和基于样本的稳定性统计。
- 飞书低噪音通知。

### P1：服务主线的增强

- 更完整的行情字段归一化。
- 盘中滑点、排队、开板和分钟线证据。
- 全市场主升根因扫描作为证据层：分析产业逻辑、价值承接、资金吸引、持续性和买点，但不写入模拟盘，不改变默认买入路由。
- 稳定性样本达到 30/50/100 笔后的服务端策略边界建议。
- 历史回放使用隔离账本，不污染真实模拟盘。
- 更清晰的主线证据中心和收益曲线。

### P2：首版不做

- 多战法默认入口。
- 自动实盘交易。
- 旁支交易执行入口。
- 复杂多账户管理。
- 泛 AI 中心。
- 花哨大屏。

## 4. 页面和需求设计规则

后续新增或改版功能前，必须先回答：

1. 它是否让 `今日决策 -> 模拟盘指挥单 -> 盘中买卖纪律 -> 晚评复盘 -> 收益/回撤证据` 更清晰？
2. 它是否直接服务主板 10cm 主线首板？
3. 用户在这里要做出的关键判断是什么？
4. 风险、止损、仓位、T+1 后果是否在动作前可见？
5. 哪些信息可以下沉、折叠、自动化或暂缓？
6. 它是否会增加冲动交易或误操作风险？

共同约束：

- 客户端不直接决定可信交易结果。
- 业务规则不得散落在 UI 事件里。
- 新能力先归入主线首板，再决定页面位置。
- 每个关键状态变化都应该能被记录、回放或复盘。
