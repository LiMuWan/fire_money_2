# FireMoney 核心业务功能基准

## 1. 产品北极星

FireMoney 当前只验证一条纪律：主板 10cm 一进二。

用户真正要完成的是：

```text
看今日有没有一进二机会 -> 看候选位置和风险 -> 模拟盘执行纪律 -> 收盘复盘 -> 积累稳定性样本
```

首版不保留多战法、旧 demo、旁支交易流或通用交易终端能力。

## 2. 三段核心业务线

### 2.1 早盘判断

用户问题：

**今天有没有主板 10cm 一进二机会？哪个候选最值得观察？**

保留能力：

- 市场温度
- 昨日首板池
- 一进二候选
- 低位、突破、压力、均线、量能评分
- 硬拦截原因和观察提示

不做成首版主入口：

- 多战法扫描
- 独立消息中心
- 复杂主题大屏
- 与一进二无关的大量指标卡

### 2.2 盘中模拟

用户问题：

**候选触发后，模拟盘如何按纪律执行？**

保留能力：

- 模拟买入事件
- 竞价确认、开盘触发、盘中风险三个阶段
- 仓位上限
- 结构止损 + 固定比例止损
- 严格 T+1 风险提示
- 当天止损预警
- 次日仍弱时模拟卖出
- 飞书盘中事件通知

暂缓能力：

- 自动实盘交易
- 多账户维护
- 券商 SDK 操作
- 与当前候选无关的账户总览

### 2.3 尾盘复盘

用户问题：

**今天的样本告诉我什么，稳定性是否足够？**

保留能力：

- 尾盘测评
- 成功/失败完成交易样本
- 最近完成样本摘要
- 止损触发情况
- 样本数和观察期状态
- 尾盘飞书同步最新样本摘要、稳定性阶段、下一样本门槛和边界建议
- 30/50/100 笔后的策略边界建议，由服务端基于完成样本输出

暂缓能力：

- 大型历史统计中心
- AI 实验台
- 复杂报表导出中心
- 与一进二无关的参数海

## 3. 功能优先级

### P0：必须做好

- MarketDataProvider/AkShare 行情边界
- 昨日首板池和一进二候选评分
- ST、退市、新股、非主板、高位、压力近、一字买不到等硬拦截
- 模拟盘账本
- 交易日历和自动 T+1 状态流转
- 本地调度器按早盘、盘中、尾盘推进一进二闭环，并防止同日重复触发
- 单票 8%、每天 1 笔、严格 T+1
- 完成交易样本归档和基于样本的稳定性统计
- 飞书通知结果
- 尾盘测评和稳定性观察

### P1：服务主线的增强

- 更完整的 AkShare 字段归一化
- 常驻盘中扫描调度器的运行体验和部署方式
- 稳定性样本达到 30/50/100 笔后的服务端策略边界建议
- 历史回放使用隔离账本，不污染真实模拟盘
- 更清晰的低位突破、高位接力样本分布

### P2：首版不做

- 多战法
- 自动实盘交易
- 旁支交易执行入口
- 复杂多账户管理
- 泛 AI 中心
- 花哨大屏

## 4. 页面和需求设计规则

后续新增或改版功能前，必须先回答：

1. 它是否让 `早盘判断 -> 盘中模拟 -> 尾盘复盘 -> 稳定性观察` 更清晰？
2. 它是否直接服务主板 10cm 一进二？
3. 用户在这里要做出的关键判断是什么？
4. 风险、止损、仓位、T+1 后果是否在动作前可见？
5. 哪些信息可以下沉、折叠、自动化或暂缓？
6. 它是否会增加冲动交易或误操作风险？

共同约束：

- 客户端不直接决定可信交易结果。
- 业务规则不得散落在 UI 事件里。
- 新能力先归入一进二主线，再决定页面位置。
- 每个关键状态变化都应该能被记录、回放或复盘。
