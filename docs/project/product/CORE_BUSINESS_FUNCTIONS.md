# 核心业务功能基准

## 1. 产品北极星

量化猎手 Pro 不是“展示更多股票数据”的工具，而是面向 A 股短线、盘中交易和半自动量化辅助用户的交易决策终端。

一句话定位：

**量化猎手 Pro 是一个面向短线/盘中交易者的“机会发现 -> 决策审查 -> 执行中控 -> 复盘改进”交易辅助终端。**

用户真正需要解决的问题不是信息太少，而是：

- 信息太散，盘中来不及判断。
- 候选股很多，不知道今天真正该盯哪几个。
- 策略信号有了，但不知道现在能不能下手。
- 下单前缺少风控审查、账户状态确认和二次确认。
- 执行后只看到结果，缺少回执、偏差和复盘链路。
- 参数、消息、账户、策略和执行状态分散，用户没有安全感。

产品主心智：

```text
看市场 -> 找机会 -> 做判断 -> 控风险 -> 执行 -> 复盘 -> 改策略
```

## 2. 主业务闭环

项目最重要的业务闭环压缩为一条主链路：

```text
全局态势
-> 信号扫描
-> 机会池
-> 执行审查
-> 委托提交
-> 回执跟踪
-> 单票/日终复盘
-> 策略参数改进
```

页面和功能可以丰富，但用户心智只能围绕这条主链组织。后续新增功能必须先判断属于主链、辅助证据、配置能力，还是应暂缓的扩展能力。

## 3. 核心业务功能

### 3.1 盘中机会发现

用户痛点：盘中机会变化快，人工盯盘容易漏掉主线、龙头和异动。

核心能力：

- 股票池扫描
- 题材和主线识别
- 涨停和强势股捕捉
- 观察池维护
- 盘中监控提醒
- 市场温度和风险状态判断

产品表达：

**现在市场有没有机会？机会在哪里？我该先看谁？**

### 3.2 候选股决策过滤

用户痛点：筛出来的票太多，用户真正需要的是“今天值得处理的少数候选”。

核心能力：

- 多策略推荐
- 候选池排序
- 策略评分
- 风险标签
- 入场、止损、目标位建议
- 推荐理由解释
- 一键送入执行审查

产品表达：

**这些股票里，哪些最值得今天进入交易计划？**

### 3.3 执行前风控审查

用户痛点：有信号不等于能买，真正危险的是冲动下单和条件没核对。

核心能力：

- 账户和通道状态检查
- 持仓和资金同步
- 委托建议生成
- 仓位约束
- 风险提示
- 二次确认
- 异常阻断

产品表达：

**这笔交易现在能不能做？做之前还有什么风险？**

### 3.4 半自动交易执行

用户痛点：完全自动交易风险高，纯手动又慢；用户需要安全、可控、可回溯的执行辅助。

核心能力：

- 东方财富 CSV 委托导出
- GM SDK 桥接
- 一键下单前确认
- 委托提交记录
- 执行结果日志
- 失败原因导出
- 账户、策略、桥接环境状态展示

产品表达：

**我确认后再执行，系统帮我减少重复操作和低级错误。**

### 3.5 执行结果回放与复盘

用户痛点：交易结束后只知道盈亏，不知道策略哪里对、执行哪里偏。

核心能力：

- 单票复盘
- 策略信号回放
- 买卖点标注
- 执行偏差分析
- 持仓和成交变化追踪
- 日终报告
- 次日计划生成

产品表达：

**今天为什么赚/亏？下一次要改什么？**

### 3.6 策略与参数管理

用户痛点：策略参数多，改动影响不透明，用户不敢调，也难以复现。

核心能力：

- 策略配置
- 参数优化
- 回测摘要
- 策略目录
- 参数影响范围提示
- 配置保存反馈
- 历史策略表现记录

产品表达：

**我能安全调整策略，并知道这个调整会影响哪里。**

### 3.7 消息与 AI 辅助判断

用户痛点：消息很多，但有效信息少；用户需要的是“和当前交易有关的解释”。

核心能力：

- 新闻和消息源接入
- AI 评测
- 消息中心
- 个股和题材催化解释
- 推荐逻辑说明
- 风险事件提示

产品表达：

**这条消息和我的候选股、策略、风险有什么关系？**

## 4. 功能优先级

### P0：必须保留并持续打磨

- 全局态势
- 信号扫描
- 机会池
- 执行中控
- 风控审查
- 委托导出和 GM SDK 桥接
- 执行日志
- 单票复盘
- 策略配置

P0 目标：保证用户能从盘中机会发现一路走到执行审查、委托提交和复盘改进。

### P1：可以增强

- AI 消息解读
- 参数优化
- 日终报告
- 盘中自动刷新
- 涨停专项
- 观察池联动

P1 目标：增强判断效率和复盘质量，但不能压过 P0 主链。

### P2：暂缓扩张

- 复杂多账户管理
- 过度自动化交易
- 社区或社交功能
- 花哨大屏
- 太多独立实验台
- 复杂商业化权限系统

P2 原则：这些能力不是当前痛点主链，只有当 P0/P1 闭环稳定后再评估。

## 5. 页面和需求设计规则

后续新增或改版功能前，必须先回答：

1. 这个需求解决的是哪一个真实痛点？
2. 它属于主链、辅助证据、配置能力，还是 P2 扩展？
3. 用户在这个页面要做出的关键判断是什么？
4. 页面首屏应该展示哪些必要信息，哪些应该下沉？
5. 这个能力的结果会回写到哪里？
6. 是否会增加冲动交易或误操作风险？

页面设计遵循：

- 简洁优先，不做信息大杂烩。
- 主操作清晰，风险和后果靠近操作点。
- 辅助信息下沉，复杂能力渐进展开。
- 执行类能力必须有状态、确认、回执和复盘入口。
- 所有交易相关自动化默认服务于半自动辅助，不鼓励无审查的全自动交易。

## 6. 工程落地边界

客户端优先负责：

- 用户意图捕获
- 盘面、表格、图表和状态展示
- 执行前提示和二次确认
- 交互流程和结果反馈

服务端或业务层优先负责：

- 策略计算和推荐生成
- 风控判断和异常阻断
- 账户、持仓、资金和委托状态
- 日志、回执、复盘和可追溯记录
- 外部 SDK、券商桥接、数据源适配

共同约束：

- 客户端不直接决定可信交易结果。
- 业务规则不得散落在 UI 事件里。
- 新能力先归入主链或辅助层，再决定页面位置。
- 每个关键状态变化都应该能被记录、回放或复盘。
