# FireMoney 核心业务功能基准

## 1. 产品北极星

FireMoney 是面向短线/盘中交易者的交易辅助终端。用户真正要完成的不是浏览更多信息，而是在盘中用最短路径完成一个可信动作：

```text
看信号 -> 看风险 -> 点确认 -> 看回执 -> 看一句复盘
```

首版只围绕这条路径做深，不把旧页面结构当作产品目标。

## 2. 三段核心业务线

### 2.1 市场判断

用户问题：

**现在有没有值得处理的机会？我应该先看谁？**

保留能力：

- 市场温度和风险状态
- 信号扫描
- 前排候选
- 候选理由、评分、风险标签
- 进入执行前的观察提示

合并能力：

- 全局态势
- 信号扫描
- 机会池

不做成首版主入口：

- 独立消息中心
- 多层新闻墙
- 花哨大屏
- 与当前机会无关的大量指标卡

### 2.2 执行中控

用户问题：

**这个机会能不能做？做之前必须确认什么？**

保留能力：

- 执行前风控审查
- 阻断原因和警告
- 仓位约束
- 委托草稿
- 用户二次确认
- 回执跟踪
- 执行日志

暂缓能力：

- 无人值守自动交易
- 多券商维护中心
- 复杂多账户管理
- 与当前委托无关的账户总览

### 2.3 复盘改进

用户问题：

**这次执行告诉我下一次要改什么？**

保留能力：

- 单次执行结论
- 执行偏差
- 经验要点
- 下一步策略边界调整
- 参数影响说明

合并能力：

- 单票复盘
- 策略配置

暂缓能力：

- 大型历史统计中心
- AI 实验台
- 复杂报表导出中心
- 与当前策略无关的参数海

## 3. 功能优先级

### P0：必须做好

- 市场判断
- 信号扫描
- 前排候选
- 执行审查
- 委托确认
- 回执跟踪
- 复盘改进
- 策略边界提示

P0 目标：用户可以从一个候选机会一路走到确认、回执和复盘，不被无关入口打断。

### P1：服务主线的增强

- 观察池联动
- 日终报告
- 参数影响预览
- 消息解释
- 盘中自动刷新
- 涨停专项

P1 原则：只增强判断效率和复盘质量，不增加新的首版主入口。

### P2：首版不做

- 独立消息中心
- 泛 AI 中心
- 复杂多账户管理
- 过度自动化交易
- 社区或社交功能
- 花哨大屏
- 复杂商业化权限系统

## 4. 页面和需求设计规则

后续新增或改版功能前，必须先回答：

1. 它是否让 `看信号 -> 看风险 -> 点确认 -> 看回执 -> 看一句复盘` 更清晰？
2. 它属于 `市场判断`、`执行中控`、`复盘改进` 的哪一段？
3. 用户在这里要做出的关键判断是什么？
4. 哪些信息必须在动作发生前可见？
5. 哪些信息可以下沉、折叠、自动化或暂缓？
6. 它是否会增加冲动交易或误操作风险？

页面设计遵循：

- 一屏只服务一个主问题。
- 主操作清晰，风险和后果靠近操作点。
- 辅助信息默认下沉。
- 执行类能力必须有确认、状态、回执和复盘入口。
- 所有可见文本优先来自内容配置或共享文案，方便后续多语言。

## 5. 工程落地边界

客户端优先负责：

- 用户意图捕获
- 盘面、表格、图表和状态展示
- 执行前提示和二次确认
- 交互流程和结果反馈
- 内容配置加载

服务端或业务层优先负责：

- 策略扫描和评分
- 风控判断和异常阻断
- 委托草稿生成
- 账户、持仓、资金和委托状态
- 日志、回执、复盘和可追溯记录
- 外部 SDK、券商桥接、数据源适配

共同约束：

- 客户端不直接决定可信交易结果。
- 业务规则不得散落在 UI 事件里。
- 新能力先归入三段主线，再决定页面位置。
- 每个关键状态变化都应该能被记录、回放或复盘。
