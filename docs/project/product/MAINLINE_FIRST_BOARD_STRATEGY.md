# FireMoney 主线首板龙头预判产品线

## 当前北极星

FireMoney 当前只服务一条核心链路：

```text
主线首板龙头预判 -> 封板纪律确认 -> 次日一进二确认 -> 模拟盘验证 -> 尾盘复盘 -> 稳定性观察
```

一进二不再作为孤立战法入口，而是作为首板候选次日强弱确认和 T+1 风险处理点。产品第一阶段只验证这条链路是否长期可测、长期收益曲线能否向上。

## 保留边界

- 只做 A 股主板 10cm。
- 只观察主线首板龙头候选，不做战法超市。
- 只做事件驱动模拟盘，不连接真实账户，不自动下单。
- 只保留早盘判断、盘中事件、尾盘复盘、稳定性观察。
- 飞书只承担通知和审计，不影响策略继续运行。

## 候选判断

候选必须同时过三道核心判断：

- 封板纪律：封板资金、封单占比、炸板风险和一字买不到风险。
- 主线强度：题材是否在当日主线里，市场温度是否支持接力。
- 龙头辨识度：是否比普通跟风票更早、更强、更容易成为资金焦点。

策略候选契约保留 `sealing_score`、`mainline_score`、`leader_score`、`leader_label`、`strategy_tags` 和 `discipline_summary`，客户端只展示服务端给出的结论，不重新计算交易判断。

## 硬拦截

以下情况不能进入模拟买入：

- 非主板 10cm、ST、退市、新股前 5 日、创业板、科创板、北交所。
- 次日确认不是红盘开，或开盘涨幅超过 4.5%；候选可以记录，但不进入模拟买入。
- 高位乖离过大、连续大涨后首板、左侧压力过近。
- 成交额过低、承接不足、一字买不到。
- 封板资金不足。
- 低位平台突破缺少市场宽度确认：昨日主板首板少于 45 家，或今日可执行候选少于 6 个。
- 主线强度不足。
- 龙头候选辨识度不足。

## 运行闭环

- `morning`：生成早盘判断，输出市场温度、候选、拦截和风险。
- `watch`：按 `scan/auction/open/risk` 推进盘中事件和模拟盘。
- `eod`：归档尾盘测评、完成样本和下一交易日边界建议。
- `backtest`：用隔离账本做历史回放，不污染真实模拟盘。
- `backtest-audit --brief`：按数据准备、规则版本、执行回测、准入结论输出可测试边界。
- `stability`：读取闭环样本，少于 30 笔只显示观察期。
- `beta-plan --brief`：只读生成下一交易日上线测试计划、阻断项和推荐命令；完整 JSON 留给排查和程序读取。
- `beta-rehearsal`：用样例行情和隔离账本跑完整天流程，不发飞书，不污染真实模拟盘。
- `beta-check` / `beta-start`：上线测试前必须通过飞书、行情、账本和调度体检。

## 上线测试红线

- AkShare 不可用时只生成 blocked 报告，不产生模拟买入。
- 飞书凭证只能来自环境变量或被忽略的 `.firemoney/feishu.env`，不得写入仓库。
- 当天跌破止损只预警，T+1 仍弱才模拟卖出。
- 买入前必须生成卖点计划：默认跌破结构/4.25% 止损预警，盈利 16% 第一止盈，强势达到 8.25% 后用 0.10% 回撤保护。
- 主线持续性低于 45 分视为衰减；T+1 已到时优先退出，不用新闻消息硬扛。
- 单票仓位不超过 8%，每天最多 1 笔。
- 未达到 30 笔闭环样本前，不允许给出策略稳定性结论。

## 主线持续性

主线持续性只作为持仓纪律和风险提示，不单独触发买入。第一版证据来自三类：

- 价格证据：同主线候选数量、近涨停强度、封板质量。
- 消息证据：AkShare 东方财富个股新闻 `stock_news_em` 抓到的相关新闻数量和标题。
- 市场证据：市场温度、主线分数、龙头辨识度。

消息抓取失败时不阻断策略，但飞书会提示“未抓取到新的主线消息”；此时只按价格、封板和 T+1 纪律处理。

## 回测准入

参考标准流程固定为四步：

1. 数据准备：检查可用交易日、样本数量、幸存者偏差、执行颗粒度。
2. 策略编写：当前规则版本必须固化为主线首板龙头候选、T+1、止盈止损和主线衰减退出。
3. 执行回测：使用隔离账本，禁止污染真实 `.firemoney/paper_trades.json`。
4. 结果准入：样本少于 30 笔只观察；达到 30/50/100 笔后再进入策略边界复核。

当前 AkShare 免费数据适合做第一阶段流程验证，不等同专业 Point-in-Time 数据；长期收益判断要逐步补足退市股票、复权校验、分钟线/Tick 级成交和滑点。完整回测默认要求主板股票池至少达到 2500 只；如果沪深任一交易所名单临时不可用，研究脚本会先用 AkShare A 股列表和本地历史缓存补齐，并把来源写入 `data_quality.universe_warnings`，仍不足时直接中止，避免用缺失样本误判策略。

## 产品口径回测

回测不能按“所有候选都买”判断策略，也不能使用未来最高价、未来收盘价给当天候选排序。FireMoney 的有效性只看产品真实执行口径：

```text
首板候选 -> 硬拦截 -> 低位突破市场宽度确认 -> 次日红盘且不高于 4.5% 开盘确认 -> 当天可见字段排名 -> 每天最多 1 笔 -> 单仓不重叠 -> 严格 T+1 -> 卖点纪律结算
```

默认卖点纪律固定为：买入价下方 4.25% 止损，T+1 后才允许卖出；浮盈达到 16% 执行第一止盈；强势达到 8.25% 后使用 0.10% 回撤保护；持仓 2 个交易日未达到 4% 以上优势时纪律退出。研究脚本输出里要优先看 `product_portfolio.one_position_no_overlap`，而不是 `filtered_strategy_candidates`。

## 历史逐日回放

新增 `replay` 入口用于回答“如果我在历史某一天按本战法介入，后面实际盈亏比是多少”：

```powershell
python -m client.desktop.firemoney_client.one_to_two_cli replay --brief --trade-date 2026-04-24 --holding-days 3
```

回放纪律固定为：先用 `trade-date` 当天可见的一进二候选池和策略配置选股；候选确定后，才读取后续日线做 T+1、止损、第一止盈、强势回撤和最长持仓退出结算。后续价格只用于计算卖点、收益率、最大顺风/逆风和盈亏比，不参与候选评分。

第一版使用日线高低收做执行近似；如果同一根日线同时碰到止损和止盈，按保守止损优先处理。真实长期评价仍需要更干净的 Point-in-Time 快照、退市样本、复权校验、分钟线/Tick、滑点和手续费。
