# FireMoney 核心业务线

## 1. 用户真正要完成的事

用户打开 FireMoney，不是为了看更多页面，而是为了更快完成一个可信交易动作：

```text
现在能不能看机会 -> 哪一个最值得处理 -> 风险能不能过 -> 要不要确认执行 -> 结果如何 -> 下次怎么改
```

首版只服务这一条线。

## 2. 三段主入口

### 市场判断

回答：现在有没有值得处理的机会？

保留：

- 市场温度和风险状态
- 信号扫描结果
- 前排候选
- 候选进入执行前的观察提示

合并进来：

- `全局态势`
- `信号扫描`
- `机会池`

首屏不做：

- 多层新闻墙
- 大量横向指标卡
- 独立消息中心
- 复杂主题大屏

### 执行中控

回答：这个机会能不能做，做之前要确认什么？

保留：

- 风控审查结论
- 阻断原因和警告
- 委托草稿
- 用户二次确认
- 回执状态

首屏不做：

- 自动无人值守交易
- 多券商维护中心
- 与当前机会无关的账户总览
- SDK 细节暴露给普通用户

### 复盘改进

回答：这次执行给下一次带来什么改进？

保留：

- 单次执行结论
- 偏差说明
- 经验要点
- 下一步策略边界调整

合并进来：

- `单票复盘`
- `策略配置`

首屏不做：

- 大型历史统计中心
- AI 实验台
- 复杂报表导出中心
- 与当前策略无关的参数海

## 3. 最短使用路径

```text
看信号 -> 看风险 -> 点确认 -> 看回执 -> 看成交 -> 看退出 -> 看结果卡 -> 看归档
```

这条路径是产品验收标准：任何新增功能如果不能让这条路径更清晰、更快或更可信，就不进入首版主入口。

## 4. 当前已完成的闭环

当前本地预览已经打通：

- 信号扫描筛出前排候选。
- 风控审查给出仓位限制、警告和下一步。
- 用户确认后生成 CSV 委托文件。
- 券商端回执 CSV 写回后，回执状态变为 `accepted`。
- 成交明细写回后，复盘展示成交均价、成交滑点和策略建议。
- 退出成交写回后，结果卡展示已实现盈亏和最终动作。
- 完成交易生成归档记录并持久化到 `.firemoney/trade_archives.json`。
- 客户端侧栏只展示最近归档轻量复查条，不做复杂历史中心。

## 5. 工程落点

- 客户端：只暴露 `市场判断`、`执行中控`、`复盘改进` 三个主入口。
- 服务端/业务层：输出可信扫描、风控、委托、回执和复盘结论。
- 共享契约：所有跨层字段先进入 `shared/contracts`。
- 内容配置：可见文本优先放在内容配置文件，便于后续多语言。
- 测试：smoke 必须覆盖三段入口和完整主链快照。
