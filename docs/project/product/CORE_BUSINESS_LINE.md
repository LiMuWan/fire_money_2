# FireMoney 核心业务线

## 1. 用户真正要完成的事

用户打开 FireMoney，不是为了看更多页面，也不是为了追逐一堆研究线，而是为了验证一条小账户也能执行的主线首板交易纪律：

```text
今天是否有主线首板机会
-> 候选是否在主板 10cm 和 50-800 亿市值带
-> 一手成本和仓位是否可控
-> 买点、止损、止盈和取消条件是否清楚
-> 模拟盘是否按纪律写入买卖
-> 尾盘是否复盘收益、回撤和下一步
```

默认经营面只保留：

- 主线首板。
- 现金空仓。

研究线、影子样本和 AI 因子只能作为证据层或研究层，不能伪装成默认可交易策略。

---

## 2. 三段主入口

### 今日决策

回答：今天该进攻主线，还是防守空仓？

保留：

- 市场温度。
- 主线候选密度。
- 主线持续性。
- K92 情绪流动性守门。
- 今日路由和下一步命令。

不做：

- 多策略同时开仓。
- 研究线默认买入。
- 用样例收益替代真实闭环收益。

### 模拟盘执行

回答：如果有买点，模拟盘怎么买、怎么卖、何时取消？

保留：

- 股票名（代码）。
- 一手成本。
- 建议仓位和硬上限。
- 买入触发价、止损、第一目标。
- 正收益锁盈、主升保护、T+1 和时间纪律。

不做：

- 自动实盘下单。
- 无数据时强行买入。
- 为了交易频率硬做。

### 证据复盘

回答：这套规则是否真的更稳定？

保留：

- 真实模拟盘闭环样本。
- 年度/月度收益。
- 最大回撤。
- 收益覆盖过程回撤。
- 赚撤比和弱年份表现。

不做：

- 只展示总收益。
- 忽略滑点、排队、炸板和行情缺失。
- 样本不足时宣传稳定盈利。

---

## 3. AI 接入边界

当前默认经营线没有接入 OpenAI、DeepSeek、Qwen 或其他 LLM 作为买卖点决策引擎。买入、卖出、仓位、空仓仍由可回测规则和模拟盘收益守门决定。

AI 后续只允许先做：

- 复盘解释。
- 风险摘要。
- 新闻/主线证据整理。
- 异常诊断。
- 可测试因子建议。

任何 AI 生成的新因子或新战法，必须先转成确定性规则，完成 2020 起逐年、月度、回撤和摩擦压力回测，且弱年份不变差，才可能进入主线候选。

不接受“AI 说可以买”作为买点；只接受“AI 帮我们发现可测试假设，然后由回测和模拟盘证明或证伪”。

---

## 4. 当前已完成的闭环

- 样例行情可生成主线首板候选。
- 策略评分展示封板质量、主线强度、龙头特征、换手质量和位置结构。
- ST、退市、新股、创业板、科创板、北交所、高位、压力近、一字买不到等情况会被拦截。
- 模拟盘按 1 万本金、一手制、每天最多 1 笔执行。
- 行情不可用时禁止生成模拟买入。
- 当天跌破止损只预警，T+1 仍弱才模拟卖出。
- 飞书通知只推早评、真实模拟买入、真实模拟卖出、晚评。
- 调度器能按早评、盘中、晚评推进主线，并通过状态文件防止同日重复触发。
- 尾盘测评和稳定性报告共享闭环样本、收益质量、下一样本门槛和策略边界建议。
- 样本不足 30 笔时保持观察期，不能输出稳定盈利结论。

## 5. 工程落点

- `client/`：只展示服务端可信结果，不重新计算交易结论。
- `server/firemoney_server/application/`：编排每日决策、模拟盘、通知和值守。
- `server/firemoney_server/domain/`：放纯交易规则和风控纪律。
- `server/firemoney_server/infrastructure/`：适配 AkShare、飞书、本地账本、SQLite 和交易日历。
- `shared/contracts/`：定义跨端 DTO。
- `framework/`：沉淀通用配置、存储、调度和通知抽象，不依赖 FireMoney 业务。

---

## 6. 产品验收标准

任何新增功能如果不能让下面这条路径更清晰、更快或更可信，就不进入默认主入口：

```text
今日决策 -> 模拟盘指挥单 -> 盘中买卖纪律 -> 晚评复盘 -> 收益/回撤证据
```
