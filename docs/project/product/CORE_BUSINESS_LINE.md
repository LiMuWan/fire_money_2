# FireMoney 核心业务线

## 1. 用户真正要完成的事

用户打开 FireMoney，不是为了看更多页面，而是为了验证一条 1 万小账户也能执行的一进二交易纪律：

```text
今天有没有一进二机会 -> 哪个候选位置最好 -> 一手成本是否可控 -> 风险和止损在哪里 -> 模拟盘怎么执行纪律 -> 尾盘怎么复盘 -> 样本稳定性如何
```

首版只服务这一条线。当前产品默认资金口径是 1 万小账户，不再用 10 万账户的 8% 仓位幻觉来生成不可执行的买点。

## 2. 三段主入口

### 市场判断

回答：今天有没有主板 10cm 一进二机会？

保留：

- 市场温度和风险状态
- 昨日首板池
- 一进二候选
- 低位/突破/压力/均线/量能评分

合并进来：

- `全局态势`
- `昨日首板筛选`
- `一进二候选池`

首屏不做：

- 多层新闻墙
- 大量横向指标卡
- 独立消息中心
- 复杂主题大屏

### 执行中控

回答：候选触发后，模拟盘如何执行纪律？

保留：

- 阻断原因和警告
- 模拟买入事件
- 一手可买性和仓位上限
- 结构止损 + 比例止损
- 严格 T+1 风险提示
- 盘中止损预警

首屏不做：

- 自动实盘交易
- 多账户维护中心
- 与当前机会无关的账户总览
- SDK 细节暴露给普通用户

### 复盘改进

回答：今天的样本给下一次带来什么改进？

保留：

- 尾盘测评
- 成功/失败样本
- 止损触发情况
- 样本数和观察期状态
- 下一步策略边界建议

合并进来：

- `模拟盘复盘`
- `稳定性评估`

首屏不做：

- 大型历史统计中心
- AI 实验台
- 复杂报表导出中心
- 与当前策略无关的参数海

AI 接入边界：

- 当前默认经营线没有接入 OpenAI、DeepSeek、Qwen 或其他 LLM 作为买卖点决策引擎；买入、卖出、仓位、空仓仍由可回测规则和模拟盘收益守门决定。
- AI 后续只允许先做复盘解释、风险摘要、新闻/主线证据整理、异常诊断和研究建议，不允许绕过 `paper-backtest`、`strategy-decision`、`paper-decision`、收益守门和飞书低噪声边界。
- 任何 AI 生成的新因子或新战法，必须先转成确定性规则，完成 2020 起逐年/月度/回撤/摩擦压力回测，且弱年份不变差，才可能进入主线候选。
- 不接受“AI 说可以买”作为买点；只接受“AI 帮我们发现可测试假设，然后由回测和模拟盘证明或证伪”。
- AI 因子准入流程固定为：AI/人工提出假设 -> `AIFactorResearchGate` 检查 PIT、安全样本、验证段、弱年份、最大回撤、赚撤比 -> 只允许进入 shadow research -> 真实模拟盘闭环继续验证 -> 单独评审是否进入主线。
- 即使 `AIFactorResearchGate` 通过，返回的也是 `shadow_research_only`，不能写模拟盘账本、不能发买卖通知、不能改变 `strategy-decision` 和 `paper-decision`。

## 3. 最短使用路径

```text
早盘判断 -> 候选评分 -> 模拟买入 -> 止损/T+1 风险 -> 尾盘测评 -> 稳定性观察
```

这条路径是产品验收标准：任何新增功能如果不能让这条路径更清晰、更快或更可信，就不进入首版主入口。

## 4. 当前已完成的闭环

当前本地预览已经打通：

- 样例行情生成一进二候选。
- 策略评分展示首板、竞价、位置、题材和流动性。
- 高位、压力近、创业板、ST/退市/新股、一字买不到等情况被拦截。
- 模拟盘按 1 万本金、一手制、每天 1 笔执行；常态目标 18%，降档目标 12%，单票硬上限 35%，收益守门降档时硬上限 20%，一手成本超过上限时直接空仓。
- 当天跌破止损只预警，次日仍弱才模拟卖出。
- 飞书通知结果作为业务状态展示，发送失败不影响策略运行。
- 本地调度器可以按早盘、盘中、尾盘时间推进同一条主线，并防止同日重复触发。
- 尾盘测评和稳定性报告共享同一套稳定性阶段、下一样本门槛、最近完成样本和策略边界建议；样本不足 30 笔时保持观察期，达到 30/50/100 笔后再由服务端输出阶段性策略边界建议。
- K92 情绪流动性系统只作为研究影子系统，负责解释龙头进攻、低位补涨、题材切换和退潮空仓，不写模拟盘、不发买卖通知；未完成 2020-2026 分年/月度/回撤验证前，不进入默认经营线。

## 5. 工程落点

- 客户端：只暴露一进二专项台。
- 服务端/业务层：输出可信候选、评分、风控、模拟盘事件、飞书结果和复盘结论。
- 共享契约：所有跨层字段先进入 `shared/contracts`。
- 配置：策略边界放在一进二 JSON 配置，密钥只走环境变量。
- 测试：smoke 必须覆盖候选评分、硬拦截、模拟盘 T+1、飞书安全失败和预览输出。
