# Fire Money Pro UI 商业化改造需求

## 1. 目标

将当前产品从“功能集合型桌面工具”升级为“面向日内交易与盘中决策的专业终端”，统一品牌感、信息层级、交互反馈与执行闭环。

本需求必须服从项目核心业务功能基准：[CORE_BUSINESS_FUNCTIONS.md](C:/Users/18335/Documents/New%20project/docs/CORE_BUSINESS_FUNCTIONS.md)。所有 UI 改版都围绕一条主链路组织：

```text
全局态势 -> 信号扫描 -> 机会池 -> 执行审查 -> 委托提交 -> 回执跟踪 -> 单票/日终复盘 -> 策略参数改进
```

页面可以丰富，但不能把产品重新做成信息展示大杂烩。每个页面都必须帮助用户更快完成“看市场、找机会、做判断、控风险、执行、复盘、改策略”中的某一步。

核心目标：

- 建立统一的商业化视觉系统，避免页面各自为政。
- 强化“投研 -> 推荐 -> 审查 -> 提交 -> 复盘”的链路感。
- 让用户在任意页面都能感知市场状态、执行进度和系统运行状态。
- 所有功能页都要具备明确的入口、状态、结果反馈和下一步动作。

## 2. 产品定位

- 产品名称：`Fire Money Pro`
- 定位：专业短线交易决策终端
- 目标用户：高频盯盘用户、短线交易员、主线题材交易者、量化辅助决策用户
- 核心心智：更快发现机会，更稳完成执行，更清楚复盘结果

## 3. 统一设计系统

### 3.1 品牌层

- 顶部必须有统一品牌头部，承载产品名、定位描述、全局状态和快捷导航。
- 品牌气质应偏“专业终端、机构看盘、执行系统”，避免工具化和 demo 感。
- 所有主界面应共享一致的色彩语义、圆角、阴影、边框密度、信息卡片样式。

### 3.2 颜色语义

- 主色：冷静金融蓝，用于主按钮、导航激活态、关键焦点。
- 强调色：交易金，用于重点数字、核心指标和高优先级提醒。
- 成功色：绿色，用于已提交、正向执行、通过校验。
- 警示色：橙色，用于待审、待确认、处理中。
- 风险色：红色，用于失败、拒绝、异常、风险过高。

### 3.3 字体与排版

- 一级标题：承载业务模块定位，突出“工作台”属性。
- 二级标题：用于区块标题，突出信息分层。
- 数据文字：大号高对比字体，突出决策值、执行值、状态值。
- 说明文字：低饱和辅助色，避免视觉噪音。

### 3.4 通用组件

- 顶部品牌头部
- 全局状态 Chip
- 工作台 Hero
- 指标卡 Metric Card
- 终端面板 Terminal Panel
- 执行状态标签
- 风险摘要区
- 操作按钮组
- 结果日志区

## 4. 全局交互要求

- 每个页面都必须回答 4 个问题：
  - 当前是什么页面
  - 当前状态如何
  - 用户下一步能做什么
  - 做完以后结果会在哪看到
- 所有关键操作必须有状态反馈：
  - 处理中
  - 成功
  - 失败
  - 后续动作建议
- 所有跨页面联动必须回写状态，不能停留在“跳转成功但状态不同步”。

## 5. 各工作台需求

### 5.1 总览页

- 目标：快速把握市场环境、主线题材、龙头焦点、交易温度。
- 必须包含：
  - 市场主控区
  - 主线题材摘要
  - 龙头与资金方向摘要
  - 市场决策摘要
  - 快捷跳转到推荐/交易

### 5.2 扫描页

- 目标：完成策略扫描、观察池维护和盘中监控。
- 必须包含：
  - 扫描入口
  - 当前股票池状态
  - 回测摘要
  - 观察池状态
  - 盘中预警或提醒

### 5.3 推荐页

- 目标：承接扫描与市场情绪，生成更适合盘中处理的候选池。
- 必须包含：
  - 多维筛选：题材、策略、动作、执行状态
  - 推荐池表格
  - 顶部执行统计卡
  - 今日交易计划
  - 推荐逻辑说明
  - 一键送入交易审查

### 5.4 打板页

- 目标：支持独立的打板模式监控与执行准备。
- 必须包含：
  - 打板候选列表
  - 打板温度/强度
  - 监控状态
  - 快速导出或加入交易审查的入口

### 5.5 登录页

- 目标：承载统一账户接入与券商/SDK 配置。
- 必须包含：
  - 账户信息
  - 接入渠道
  - 凭据状态
  - 安全边界提示

### 5.6 明细页

- 目标：查看个股级别的详细分析、走势和策略依据。
- 必须包含：
  - 个股画像
  - 策略评分
  - 题材与催化
  - 交易建议摘要

### 5.7 交易页

- 目标：完成执行审查、委托提交、结果追踪、盘后复盘。
- 必须包含：
  - 账户与网关状态
  - 执行摘要
  - 风控提示
  - 委托建议表
  - 提交前审查
  - 持仓变化预估
  - 执行结果日志
  - 交易复盘区

### 5.8 配置页

- 目标：管理策略参数、授权能力、盘前/盘后报告偏好。
- 必须包含：
  - 参数输入区
  - 授权层级说明
  - 影响范围提示
  - 保存后的即时反馈

## 6. 商业化改造原则

- 不做孤立页面美化，要做统一终端壳层。
- 不只强化视觉，还要强化业务状态表达。
- 不只增加信息量，要提升“看懂速度”与“处理效率”。
- 不牺牲功能完整性，所有改造必须保留原有能力路径。

## 7. 分阶段落地建议

### 第一阶段：终端壳层统一

- 顶部品牌头部
- 全局状态 Chip

- 统一视觉语义

### 第二阶段：推荐与交易一体化

- 推荐池执行状态回写
- 一键送审
- 交易前审查
- 执行结果复盘

### 第三阶段：商业终端强化

- 失败单重审
- 盘中待处理视图
- 状态统计看板
- 跨页状态追踪
