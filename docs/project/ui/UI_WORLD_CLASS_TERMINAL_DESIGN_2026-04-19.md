# 量化猎手 Pro 终端级 UI 设计方案

## 1. 走查结论

本次已实际启动 `PySide6` 客户端，并结合当前终端壳层、工作区构建器与文案配置完成界面走查。现有产品已经不是单页工具，而是具备完整闭环的多工作区交易终端，当前核心工作区包括：

- `市场机会工作台`
- `统一登录`
- `每日推荐`
- `交易执行`
- `策略扫描`
- `打板专项`
- `明细复盘`
- `参数配置`

现状优点：

- 已有统一品牌头部、状态条、Hero 区、指标卡、终端面板与消息链路。
- 推荐页与交易页已经形成“推荐 -> 送审 -> 执行 -> 回执”的业务闭环。
- 总览页、扫描页、推荐页、交易页、复盘页之间已经具备联动基础。

现状不足：

- 页面命名偏长，标签像“功能入口”，不像“机构终端工作区”。
- 文案语气有时偏提示型、说明型，不够像交易中控和执行系统。
- 图表、表格、状态标签、按钮层级已具备基础，但“系统语义”和“行情语义”还可以进一步分离。
- 目前页面气质更像“强功能桌面应用”，距离“世界级金融机构交易终端”还差一层统一的品牌纪律、字体纪律和信息纪律。

## 2. 设计总目标

把当前产品从“强功能交易工具”升级为“机构级盘中决策终端”。

### 2.1 最高优先级执行原则

后续所有改版统一按下面的优先级执行，不允许再反过来：

- 第一优先级：先按本设计文档定义的品牌纪律、信息层级、页面结构和终端语言，完成整体 UI 重新设计。
- 第二优先级：先判断页面是否需要拆分、重排、收紧或改成子视图；页面视觉结构优先于代码结构。
- 第三优先级：只有当设计落地明确需要时，才进行代码解耦、抽配置、拆 helper 或重构主窗口逻辑。

补充约束：

- 不允许把“代码更优雅”当成先于“UI 整体设计正确”的目标。
- 不允许为了重构而重构；所有重构必须服务于页面设计、视觉统一或信息架构调整。
- 当“继续重构代码”和“继续统一页面设计”发生冲突时，默认优先做页面设计。

终端气质建议统一为 4 个关键词：

- 冷静
- 权威
- 高密度
- 可执行

设计原则：

- 不做花哨科技感，做可信赖的金融终端感。
- 不追求炫技动效，优先保证判断速度和执行效率。
- 不堆更多信息，优先强化主次层级、状态语义和下一步动作。
- 所有页面都必须回答 4 个问题：我在哪、现在什么状态、下一步做什么、结果在哪看。

### 2.1 页面设计硬规则

后续所有页面改版都按下面这组规则执行，不再按“能塞下就先塞”的方式临时扩展：

- 一个 `toggle` 只控制一个明确页面或一个明确辅助层，不允许一个开关同时切多个主视图。
- 一个页面只承载一条主链路，不允许把两个不同 workflow 阶段堆进同一主页面。
- 一个页面首屏最多只允许一个主判断区；其他能力只能是辅助证据、子视图或次级工具。
- 一个页面的默认首屏节奏统一为：`Hero -> 状态条 -> 判断条 -> 指标/摘要 -> 子视图`。
- 当页面已经有可复用的终端组件时，优先复用，不再新造一套视觉结构。

优先复用的页面级原子组件：

- `workspace hero`
- `status banner`
- `workspace focus strip / judgment strip`
- `workspace stage summary`
- `summary cards`
- `action row`
- `terminal panel`
- `terminal table`
- `note panel`

页面拆分判定规则：

- 一个页面出现两个以上同权重主任务，必须拆。
- 一个 `toggle` 背后如果切换的是两个不同对象、两个不同流程阶段或两个不同结果区，必须拆。
- 首屏如果出现三个以上同权重大区块，优先拆成子页面，而不是继续压缩。
- 如果用户在一个页面里需要在“判断 / 配置 / 执行 / 复盘”之间来回切心智模式，必须拆。

页面布局规则：

- Hero 只负责说明“这是哪里、最重要的判断是什么、看哪几个指标”，不承担大段说明书职责。
- 状态条只说当前状态，不说长解释。
- 判断条只说“看什么 / 本页动作 / 下一步”，不堆完整教程。
- 辅助工具区默认不抢首屏主位，优先进入 Drawer、折叠区、More Menu 或次级 Tab。
- 表格、图表、日志、说明块都要围绕同一个页面主链组织，不能各自成页。

控件复用规则：

- 同类页面复用同一套骨架：不要为每个页面发明一套新的状态条、判断条和 action row。
- 同类按钮复用同一套命名和 role 语义：主操作、次操作、辅助操作必须全局一致。
- 同类空态复用同一套结构：标题 / 当前状态 / 下一步。
- 同类辅助动作复用同一套短标签和 tooltip 词典。

新增或改版页面前必须先回答：

1. 这个页面的唯一主链路是什么？
2. 首屏的状态条和判断条分别展示什么？
3. 哪些能力属于辅助层，应该折叠或下沉？
4. 当前是否已有可复用组件骨架？

## 3. 品牌与命名体系

### 3.1 终端品牌写法

建议保留现有品牌资产，统一写法如下：

- 中文品牌：`量化猎手 Pro`
- 英文品牌：`QUANT HUNTER PRO`
- 产品描述：`Institutional Trading Terminal`

建议在终端壳层中采用“双层品牌”：

- 顶部品牌 Pill：`QUANT HUNTER PRO`
- 主标题：`量化猎手 Pro`
- 副标题：`机构级交易决策终端`

### 3.2 窗口标题规范

建议统一为：

`量化猎手 Pro v2.2 | {工作区} | {关键状态}`

示例：

- `量化猎手 Pro v2.2 | 全局态势 | 市场已同步`
- `量化猎手 Pro v2.2 | 机会池 | 候选 12 | 计划 5`
- `量化猎手 Pro v2.2 | 执行中控 | 待审 3 | 已提交 2`

### 3.3 工作区命名规范

建议把当前标签改成更短、更机构化、更适合高频扫描的名称：

| 当前名称 | 建议 Tab 名称 | Hero 标题 | Hero 副标题 |
| --- | --- | --- | --- |
| 市场机会工作台 | 全局态势 | 市场总控台 | 主线、资金、消息与交易温度在同一视图完成初判。 |
| 统一登录 | 接入中心 | 统一接入中心 | 账户、通道、凭据与风控边界统一管理。 |
| 每日推荐 | 机会池 | 机会池与计划台 | 先定焦点，再过门槛，再进入执行审查。 |
| 交易执行 | 执行中控 | 交易执行中控台 | 委托审查、风险闸门、回执跟踪与执行复盘统一处理。 |
| 策略扫描 | 信号扫描 | 信号扫描与监控台 | 扫描、观察池与盘中监控在同一链路内联动。 |
| 打板专项 | 涨停策略 | 涨停策略专项台 | 聚焦前排强势股、回封质量与执行准备。 |
| 明细复盘 | 单票复盘 | 单票复盘与决策台 | 单票画像、交易依据、执行轨迹与复盘结论集中查看。 |
| 参数配置 | 策略配置 | 策略与风控配置台 | 管理策略参数、风险档位、消息源与 AI 评测边界。 |

结论：

- Tab 名称控制在 4 到 6 个汉字。
- Hero 标题保留“台”“中控”“中心”这类机构终端语义。
- Hero 副标题只说本页核心价值，不写流程说明书。

## 4. 视觉系统规范

### 4.1 色彩策略

终端必须把“系统状态色”和“行情涨跌色”分开。

原因：

- A 股场景里，涨是红、跌是绿。
- 但系统里“成功”仍然应该是绿，“失败”仍然应该是红。
- 如果两套语义混用，用户在交易页会产生误判。

### 4.2 基础色板

建议以“石墨黑 + 机构蓝 + 交易金”为主线：

| Token | 颜色 | 用途 |
| --- | --- | --- |
| `bg/base` | `#0B1117` | 应用总背景 |
| `bg/surface-1` | `#101922` | 一级面板背景 |
| `bg/surface-2` | `#14202B` | 二级面板背景 |
| `bg/surface-3` | `#182532` | 选中或高亮面板 |
| `line/subtle` | `#223140` | 默认边框 |
| `line/strong` | `#33506A` | 强边框、分割线 |
| `text/primary` | `#E7EEF5` | 主文本 |
| `text/secondary` | `#A8B7C6` | 次文本 |
| `text/muted` | `#728397` | 辅助说明 |
| `brand/blue` | `#4D8DFF` | 主按钮、焦点、激活态 |
| `brand/cyan` | `#69C3FF` | 图表高亮、次强调 |
| `brand/gold` | `#D8A94A` | 核心数值、优先级、关键提醒 |

### 4.3 系统状态色

| Token | 颜色 | 用途 |
| --- | --- | --- |
| `state/info` | `#4D8DFF` | 默认信息、可操作提示 |
| `state/success` | `#2FB36C` | 校验通过、提交成功、连接正常 |
| `state/warning` | `#F0A53A` | 待审、处理中、需复核 |
| `state/risk` | `#E45B5B` | 失败、拒绝、异常、阻塞 |

### 4.4 行情语义色

| Token | 颜色 | 用途 |
| --- | --- | --- |
| `market/up` | `#E25555` | 涨、走强、封板、增量资金 |
| `market/down` | `#27A36A` | 跌、走弱、风险释放 |
| `market/flat` | `#8795A5` | 横盘、中性 |

使用规则：

- 图表、涨跌幅、盘口热度使用行情语义色。
- 提交成功、连接成功、同步完成使用系统状态色。
- 不允许用“行情红绿”表达“系统成败”。

当前落地补充：

- 日线 K 线按 A 股习惯统一为 `涨红跌绿`，不再沿用海外市场的绿涨红跌。
- 计划价格线与计划标记统一为固定语义：`入场 = #69C3FF`、`止损 = #E45B5B`、`目标 = #D8A94A`。
- 回测止盈 / 止损 / 中性卖出继续使用系统成功 / 风险 / 中性色，不与行情涨跌混写。

## 5. 字体与排版规范

### 5.1 字体栈

建议使用系统可落地字体，避免依赖未授权商用字体：

- UI 正文字体：
  - `"Segoe UI Variable", "Segoe UI", "Microsoft YaHei UI", "PingFang SC", "Source Han Sans SC", sans-serif`
- 数字与核心指标字体：
  - `"Bahnschrift", "Segoe UI Semibold", "Microsoft YaHei UI", sans-serif`
- 等宽字体：
  - `"Cascadia Mono", "JetBrains Mono", "Consolas", monospace`

建议分工：

- 中文标题、正文、按钮：UI 正文字体
- 价格、收益、风险值、时间、订单编号：数字字体或等宽字体
- 日志、订单 ID、策略脚本片段、调试信息：等宽字体

### 5.2 字体层级

| 层级 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| Hero Title | 28 | 34 | 700 | 工作区主标题 |
| Workspace Title | 20 | 28 | 700 | 面板主标题 |
| Section Title | 14 | 20 | 600 | 区块标题 |
| Metric Value L | 26 | 30 | 700 | 核心指标 |
| Metric Value M | 20 | 24 | 700 | 次级指标 |
| Body | 13 | 20 | 500 | 正文说明 |
| Table | 12 | 18 | 500 | 表格正文 |
| Meta | 11 | 16 | 500 | 辅助标签、来源、说明 |
| Mono | 12 | 18 | 500 | 日志、代码、订单号 |

排版规则：

- 中文不建议做大字间距。
- 英文品牌可加 `0.8px` 字距，增强机构终端感。
- 数字必须右对齐。
- 百分比、收益率、金额列统一使用数字字体。

## 6. 栅格、间距与面板规范

### 6.1 空间系统

统一采用 4px 基线：

- `4 / 8 / 12 / 16 / 20 / 24 / 32`

推荐：

- 应用外边距：`16`
- 工作区内部间距：`12`
- 面板内边距：`14`
- 指标卡内边距：`12`
- 表格上方标题与状态区：`10`

### 6.2 圆角与边框

| 元素 | 圆角 |
| --- | --- |
| 主面板 | `14px` |
| 指标卡 | `12px` |
| 输入框 | `10px` |
| 按钮 | `10px` |
| Chip | `999px` |

边框规则：

- 默认边框：`1px solid #223140`
- 焦点边框：`1px solid #4D8DFF`
- 风险边框：左侧 `3px` 强调，不做整块大红

### 6.3 阴影

建议弱化大面积阴影，使用“边框 + 深浅层级”代替浮夸投影。

推荐：

- 面板阴影：`0 6px 18px rgba(0,0,0,0.18)`
- 焦点卡阴影：`0 10px 24px rgba(0,0,0,0.22)`

## 7. 组件规范

### 7.1 顶部终端壳层

顶部 Header 应始终包含：

- 品牌 Pill：`QUANT HUNTER PRO`
- 产品标题：`量化猎手 Pro`
- 产品描述：`机构级交易决策终端`
- 全局状态 Chip：市场、连接、推荐、执行、消息
- 当前工作区状态摘要

文案模板：

- `市场已同步`
- `账户已接入`
- `机会池已更新`
- `待审 3`
- `消息 5 条`

### 7.2 Hero 工作区头部

每页 Hero 只做 3 件事：

- 说明这里是什么工作区
- 给出这一页当前最重要的判断
- 给出 2 到 3 个关键指标

Hero 模板：

- 标题：`交易执行中控台`
- 副标题：`委托审查、风险闸门、回执跟踪与执行复盘统一处理。`
- Badge 1：`账户状态 / 已连接`
- Badge 2：`待审委托 / 3`
- Badge 3：`今日回执 / 12`

### 7.3 指标卡 Metric Card

指标卡统一三段：

- Caption：说明看什么
- Value：核心值
- Accent：当前解释

示例：

- Caption：`执行准备度`
- Value：`78`
- Accent：`已满足送审门槛`

禁止：

- 一张卡塞进两行以上解释
- 标题、数值、提示混成一段

### 7.4 Terminal Panel

终端面板标题区统一结构：

- 左：标题
- 中：状态标签
- 右：主动作按钮

推荐标题命名：

- `主线看板`
- `委托执行台`
- `执行回执`
- `盘中监控`
- `统一消息中心`

### 7.5 表格规范

表格是交易终端的核心，不建议继续使用“通用后台表格视觉”，应转为“高密度机构终端表格”。

规范：

- 表头高度：`32`
- 行高：`30`，焦点模式 `34`
- 字号：`12`
- 表头字重：`600`
- 表格正文：`500`
- 当前选中行：深蓝底 + 左侧蓝色焦点线
- Hover：只提升一层亮度，不加描边动画
- 金额、收益、价格、仓位、时间、置信度右对齐

列语义建议：

- `名称 / 代码` 左对齐
- `动作 / 状态` 居中
- `价格 / 仓位 / 收益 / 置信度` 右对齐
- `来源 / 标签 / 主线` 使用 Chip 或轻标签样式

### 7.6 图表规范

图表风格建议从“技术展示”升级为“决策支持图表”：

- 背景：与面板一致，不单独发亮
- 网格线：低对比度
- K 线：A 股语义，涨红跌绿
- MA 线：蓝 / 金 / 灰，不使用高饱和紫色
- 关键价位：用 `brand/gold`
- 计划入场、止损、目标位：统一为三种固定语义色

推荐：

- 入场：`#69C3FF`
- 止损：`#E45B5B`
- 目标：`#D8A94A`

### 7.7 按钮体系

按钮必须从“功能按钮”升级为“执行按钮层级”。

分成 4 级：

- Primary：主动作，如 `送入执行审查`
- Secondary：次动作，如 `生成交易计划`
- Ghost：跳转类，如 `查看复盘`
- Danger：高风险动作，如 `重置模拟盘`

按钮文案规则：

- 动词在前
- 8 个汉字以内
- 不写含糊词

推荐写法：

- `刷新市场`
- `生成机会池`
- `生成交易计划`
- `送入执行审查`
- `同步账户`
- `查看回执`
- `导出报告`

不推荐写法：

- `去看看`
- `快速处理一下`
- `做交易`

### 7.8 状态标签与 Banner

Banner 规范：

- 只写一条结论
- 句式为“状态：当前阶段 | 当前阻塞 | 下一动作”

示例：

- `交易状态：待审 3 笔 | 风控闸门已开启 | 先复核前两笔高优先委托`
- `推荐状态：机会池已更新 | 计划未生成 | 先输出今日交易计划`
- `扫描状态：本地扫描完成 | 观察池已同步 | 可转入推荐池复核`

Chip 规范：

- 市场：`强 / 中 / 弱`
- 连接：`已连接 / 待配置 / 异常`
- 执行：`待审 / 已提交 / 待回执 / 已成交`
- 风险：`低 / 中 / 高`

## 8. 文案规范

### 8.1 文案语气

统一采用“交易中控口吻”，避免教程式和口语化。

建议语气：

- 判断式
- 中立
- 可执行
- 有下一步建议

避免：

- 过度解释
- 情绪化表达
- 口语化感叹句
- 像 Demo 的提示语

### 8.2 标题规范

标题结构：

- `对象 + 台`
- `对象 + 中控`
- `对象 + 中心`

例如：

- `市场总控台`
- `机会池与计划台`
- `交易执行中控台`
- `统一接入中心`

### 8.3 副标题规范

副标题只写这一页最核心的价值，不超过 28 个汉字。

推荐：

- `先定焦点，再过门槛，再进入执行审查。`
- `委托审查、风险闸门与回执跟踪统一处理。`
- `单票画像、交易依据与执行轨迹集中查看。`

### 8.4 状态文案规范

统一模板：

- `{模块}状态：{当前状态} | {当前阻塞或条件} | {下一动作}`

### 8.5 空状态文案规范

统一三层：

- 标题：4 到 8 个字
- 提示：一句说明当前缺什么
- 动作：一个主按钮，一个次按钮

示例：

- 标题：`等待机会池`
- 提示：`市场数据同步后，将生成今日可执行候选与计划链路。`
- 动作：`刷新市场` / `载入示例`

### 8.6 页内正文风格

建议每个正文模块使用“结论优先”：

- 第一行：结论
- 第二行：证据
- 第三行：下一步

示例：

`当前不建议追价。`

`主线强度尚可，但承接与持续性未通过二次确认。`

`下一步：继续观察前排候选，等待回封或量价确认。`

## 10. 机构终端级细节建议

### 10.1 信息密度模式

建议增加 3 档密度：

- `标准`
- `紧凑`
- `盯盘`

定义：

- 标准：适合盘前研究
- 紧凑：适合盘中处理
- 盯盘：表格更密、图表更大、说明文字折叠

当前产品落地规范：

- 顶栏右上角提供 `主题 + 密度` 双控件，密度切换属于全局终端行为，不属于某一个页面的局部设置。
- `标准` 模式优先保留摘要、说明和留白，适合盘前研究、多面板比对和复盘阅读。
- `紧凑` 模式作为默认运行模式，优先保证主链效率、表头读法和一屏处理速度。
- `盯盘` 模式进一步压缩 Hero、面板和表格行高，优先保留焦点、主表、状态条和主动作。
- 即便用户手动切到 `标准` 模式，低于断点后仍允许进入必要的紧凑布局；即便用户切到 `盯盘` 模式，也不能破坏主链可用性。
- `盯盘` 模式允许自动下沉非主链摘要层或次级提示块，但不能让当前页面失去“我在哪 / 现在什么状态 / 下一步做什么”的答案。
- 对扫描、打板、复盘、实验这类辅助工具较多的页面，`盯盘` 模式允许把“工具台 / 导航台 / 次级摘要”自动下沉，只保留状态条、判断条、主摘要和主视图区。
- 对接入中心和策略配置，`盯盘` 模式优先保留主链表单和关键配置区，接入摘要、配置总控、风险快照这类次级首屏块可以自动下沉。
- 对总览页，`盯盘` 模式优先保留市场判断、焦点摘要、主图和机会池；`前排龙头`、`主题摘要` 这类次级证据块可以自动下沉。
- 当总览页已经形成焦点标的或机会池后，`优先级看板`、`关键摘要`、`右侧情报 Tabs` 也可以在 `盯盘` 模式下下沉，避免总览首屏重新被“辅助证据墙”占满。
- 同样地，`左侧买卖/消息 Tabs`、`副图 Tabs`、`图层控制 Tabs` 在 `盯盘` 模式下也可以让位，只保留主图和机会池作为首屏主视图。
- 当总览页已经有焦点标的或机会池后，`关键指标`、`主线看板`、`下一步动作` 这些行动说明层也可以继续下沉，避免首屏再次堆成说明墙。
- 如果这些次级证据层都已下沉，`盯盘` 模式下总览页左右侧栏本身也可以收起，让中间主图与机会池真正占据首屏主位。
- 侧栏收起后，布局应继续把主 splitter 空间回收到中间主视图区，而不是只隐藏内容却保留左右空栏。
- 同时应放开主图与机会池的高度上限，让被回收出来的空间真正回到主视图，而不是仍被旧的固定高度卡住。
- 同时，总览页中心区那组二级标题/副标题/信号说明在 `盯盘` 模式下也可以隐藏，避免与页面顶部 Hero 重复表达。
- 对机会池和执行中控，`desk summary / stage summary / 工作台横幅 / 次级摘要卡` 这类重复摘要层在 `盯盘` 模式下也可以下沉，只保留状态条、焦点、主表和工作流切换。
- 对执行中控，`执行阶段` 这类已经被状态条和焦点条覆盖的重复标签，也应在 `盯盘` 模式下继续下沉。
- 下沉这些重复摘要层后，执行中控的 splitter 空间也应优先回收给委托主区和当前委托详情，而不是只把卡片隐藏。
- 对机会池，`关键摘要卡` 在 `盯盘` 模式下也可以继续下沉；焦点状态、执行动作卡和工作流 Tabs 已经足够回答主链问题。
- 下沉这些重复摘要层后，机会池的 splitter 空间也应继续回收给 `执行审查 / 深度洞察` 主视图区，而不是只隐藏卡片。
- 同时，机会池的执行动作卡在 `盯盘` 模式下应放开高度上限，避免主链动作区仍被旧的固定高度卡住。
- 对机会池和执行中控，`workflow tabs / stage tabs` 本身也应在 `盯盘` 模式下拿到更高的高度预算，而不是继续被标准态上限限制。
- 对扫描、打板、复盘、实验、配置这些带子视图的页面，`stage summary` 在 `盯盘` 模式下也可以下沉；只保留 Tabs 本身作为切换入口即可。
- Tabs 保留后，也应在 `盯盘` 模式下拿到更高的主区高度预算，而不是继续沿用标准态的高度上限。
- 对这些页面同样成立的是：如果已经有状态条和主视图，`desk summary` 这类判断摘要条在 `盯盘` 模式下也可以继续下沉，避免重复解释。

- 市场状态

- 用小面积风险 Chip

`[级别] [模块] 结论`

示例：

- `[低] 接入中心 SDK 环境已校验通过`

## 11. 页面级改版清单

### 11.1 全局态势

- 保留现有三栏结构，但首屏只保留一个核心结论区，不要让“市场驾驶舱”“行动剧本”“盘前优先级”同时争抢视觉中心。
- 左栏定义为“输入判断区”，只放市场快照、买卖点、消息面；中栏定义为“主控判断区”，承载 Hero、图表、机会池；右栏定义为“结论区”，承载掘龙榜、主题摘要、交易结论。
- `核心指标带` 建议压缩为 4 张卡，优先显示 `市场温度 / 主线强度 / 可执行候选 / 风险偏好`。
- `机会股票池` 首屏建议只展示最重要的 6 到 8 行，其余通过滚动或跳转到机会池页处理。
- `快筛` 和 `控制` 区默认折叠是对的，但折叠态需要始终保留 1 行状态摘要，避免用户忘记当前筛选条件。

### 11.2 接入中心

- 当前页面更像表单集合，建议强化“统一接入中心”的中控感，首屏增加 3 张状态卡：`账户连接 / SDK 桥接 / 风险保护`。
- 账号字段区和连接结果区要明显分层，避免用户把“配置”和“状态”看成一个区域。
- `校验接入` 按钮必须成为唯一主按钮，`保存配置` 和 `生成模板` 退为次按钮。
- 所有敏感凭据字段建议增加脱敏态、已填写态和最近校验时间。
- 页面底部保留一条安全边界说明，明确“当前页面只负责接入与校验，不直接触发真实交易”。

### 11.3 机会池

- 当前页已经是核心业务页，建议把页面重心固定为 `当前焦点 -> 今日计划 -> 执行队列` 三段，不要让辅助洞察抢主流程。
- `当前焦点` 区建议视觉上做成整页第一焦点，明确显示 `标的 / 动作 / 准备度 / 风险 / 下一动作`。
- `主线看板`、`题材热度`、`龙头榜` 统一归入“策略判断层”；`统一消息中心`、`今日交易计划`、`执行队列` 归入“执行准备层”。
- `一键送入交易审查` 必须在当前焦点、计划表和队列表里保持一致位置与一致命名，不要多处出现不同说法。
- AI 评测只做“复核意见”，不要视觉上比真实交易计划更重。

### 11.4 执行中控

- 当前页面信息密度高，但还缺一个绝对主轴。建议固定主轴为 `执行阶段 -> 待审委托 -> 当前委托详情 -> 执行回执`。
- `账户配置`、`运行维护`、`模板生成` 等偏后台能力默认收起是对的，盘中首屏不应与委托链路抢空间。
- `主线审查 / 执行中控` 建议加强成单独的高优先级面板，承接来自机会池页的焦点票。
- `委托执行台` 表格列建议分优先级隐藏，最核心保留 `标的 / 动作 / 数量 / 价格 / 风险 / 状态 / 提交时间`。
- `执行回执` 和 `偏差复盘` 要形成上下连续关系，避免提交结果与复盘结论割裂。

### 11.5 信号扫描

- 建议把页面定位固定成“上游信号入口”，首屏只回答 3 个问题：扫到了什么、现在盯什么、能不能送去机会池。
- `信号扫描榜` 永远作为页面主表，`观察池` 和 `盘中监控` 作为联动面板，不反客为主。
- `重新扫描` 必须是唯一主按钮，`加入观察池` 与 `移出观察池` 作为次级动作，避免误操作。
- 焦点状态条建议增加 `当前焦点 / 最新动作 / 信号日期 / 送审建议` 四段。
- 回测摘要与监控摘要建议合并成统一“焦点说明区”，减少重复解释。

### 11.6 涨停策略

- 该页应呈现更强的“专项席位”感，与通用机会池形成明显差异。
- `打板候选池` 作为主表，`炸板 / 回封监控` 作为二级监控表，二者之间用统一焦点股票联动。
- 建议强化 `封板强度 / 回封概率 / 炸板风险 / 计划买点` 四类数值的视觉权重。
- 所有“导出”“加入交易审查”类动作统一收在右上角操作带，避免分散。

### 11.7 单票复盘

- 建议把当前页面收敛为“先看单票结论，再看证据，再看历史表现”的阅读顺序。
- `单票速览`、`交易决策画像`、`执行状态回放` 应排成一条清晰主链，`近期信号` 与 `历史战法统计` 作为补充层。
- 图表、交易记录、结论文本建议共享同一个当前焦点标题，减少用户在多个区域反复确认自己正在看哪只票。
- `复盘结论` 区必须保留“下一步是否继续跟踪”的明确判断，而不只是说明发生了什么。

### 11.8 策略配置

- 当前页内容多且杂，建议强制拆成 4 层：`参数层 / 风险层 / 战法层 / 外部能力层`。
- `策略参数` 与 `风险档位快照` 是最常用区域，应上移；`消息源管理` 与 `AI评测` 是增强项，应下移。
- 保存类动作建议统一成页面顶部或底部固定操作带，避免多个保存入口。
- 每次保存后都要明确提示影响范围，例如“将影响推荐池、扫描结果、交易计划生成逻辑”。

## 12. 基础分辨率规范

本项目当前工程实现已经具备以下基础窗口约束：

- 默认窗口约为 `1380 x 880`
- 当前最小窗口约束为 `1200 x 760`
- 启动后会根据屏幕可用区域自动拉升到约 `1180~1500` 宽、`720~900` 高的可用范围

基于现有实现与终端型产品定位，建议正式定义以下分辨率规范。

### 12.1 屏幕分辨率档位

| 档位 | 屏幕分辨率 | 定位 | 说明 |
| --- | --- | --- | --- |
| `S` | `1280 x 800` 或 `1366 x 768` | 基础可用 | 允许完整运行，但必须进入紧凑布局与折叠模式。 |
| `M` | `1440 x 900` | 设计基线 | 作为主要视觉稿与组件尺寸基线。 |
| `L` | `1600 x 900` | 推荐运行 | 适合单屏盘中处理，是最推荐的标准席位分辨率。 |
| `XL` | `1920 x 1080` | 高效运行 | 适合一屏多工作区切换，图表与表格空间更充分。 |
| `XXL` | `2560 x 1440` 及以上 | 专业席位 | 适合多图表、多表格与多窗口并行。 |

### 12.2 应用窗口规范

| 类型 | 建议窗口尺寸 | 说明 |
| --- | --- | --- |
| 工程最小可用 | `1200 x 760` | 与当前代码一致，仅作为功能兜底。 |
| 产品最小推荐 | `1280 x 800` | 建议作为对外口径的最低推荐分辨率。 |
| 设计基线窗口 | `1440 x 900` | 所有主要页面稿件优先以此为基线。 |
| 单屏推荐窗口 | `1600 x 900` | 最适合交易终端首发版本的主运行规格。 |
| 高配窗口 | `1920 x 1080` | 适合完整显示多表、多图、多状态区。 |

### 12.3 Windows 缩放规范

桌面金融终端必须明确支持系统缩放，而不是只支持“物理像素”。

建议支持：

- `100%`
- `125%`
- `150%`

规范要求：

- 所有断点以 `Qt logical pixels` 作为判断依据，而不是物理像素。
- 在 `125%` 缩放下，`1920 x 1080` 仍应保证至少达到标准运行模式。
- 在 `150%` 缩放下，界面可自动进入紧凑模式，但不能破坏交易主链。

### 12.4 基础尺寸底线

| 元素 | 最小尺寸 |
| --- | --- |
| 顶部终端头部高度 | `64px` |
| Hero 高度 | `96px` 标准，`72px` 紧凑 |
| 主按钮高度 | `36px`，核心按钮 `40px` |
| 输入框高度 | `34px` |
| 表头高度 | `32px` |
| 表格行高 | `30px`，紧凑模式 `28px` |
| 主图最小高度 | `260px` |
| 主表最小可视高度 | `220px` |
| 左右侧栏最小宽度 | `220px` |

### 12.5 多屏规范

对于交易终端，建议补充多屏使用规范：

- 单屏模式：所有工作区可完整切换，但优先保证机会池与执行中控。
- 双屏模式：建议左屏常驻 `全局态势 / 机会池`，右屏常驻 `执行中控 / 单票复盘`。
- 多屏模式下，弹窗和确认框默认在当前焦点窗口打开，避免跨屏误触。

## 13. 自适应规范

自适应原则不是“整体缩小”，而是“按信息优先级折叠”。

优先级顺序固定为：

1. 全局状态、焦点标的、主按钮不能消失。
2. 主表、主图、当前委托详情不能被压缩到不可用。
3. 辅助说明、次级卡片、装饰性块优先折叠。
4. 绝不允许通过缩小字体来硬塞更多内容。

### 13.1 宽度断点

建议使用逻辑宽度断点：

| 模式 | 宽度范围 | 布局策略 |
| --- | --- | --- |
| `Wide` | `>= 1680` | 全量三栏或双主栏布局，次级面板常驻。 |
| `Standard` | `1440 - 1679` | 标准终端布局，保留三栏主结构。 |
| `Compact` | `1280 - 1439` | 侧栏收窄，说明区折叠，部分面板改 Tab 或 Drawer。 |
| `Critical Compact` | `1200 - 1279` | 只保留主链信息，次级面板全部折叠或下沉。 |
| `Unsupported` | `< 1200` | 不建议支持。 |

工程落地：

- 宽度断点常量应集中在统一配置源，不再散落在单页 patch 中各自判断。
- 手动 `标准 / 紧凑 / 盯盘` 模式只影响断点的使用倾向，不推翻最小可用宽度约束。

### 13.2 高度断点

建议使用逻辑高度断点：

| 模式 | 高度范围 | 布局策略 |
| --- | --- | --- |
| `Tall` | `>= 900` | 全量显示 Hero、图表、表格与结论。 |
| `Standard` | `820 - 899` | Hero 压缩，图表高度下降 10% 到 15%。 |
| `Short` | `760 - 819` | 说明面板折叠，主图与主表优先保留。 |
| `Unsupported` | `< 760` | 不建议支持。 |

工程落地：

- 高度断点常量应集中在统一配置源，统一驱动 Hero、状态条、表格和摘要区的收缩行为。
- `盯盘` 模式可以主动进入更高密度，但仍必须保证状态条、焦点标的和主按钮可见。

### 13.3 全局自适应规则

- 顶部 Header 始终固定，不因窗口变窄而换成多行。
- Hero 在 `Compact` 以下进入紧凑态，只保留标题、副标题和 2 到 3 个关键 Badge。
- 二级说明文本默认限制为 2 行，超出后显示“展开”。
- 面板之间优先通过 `QSplitter` 和折叠 Drawer 调整，不用整体缩放。
- 表格列按优先级隐藏，永远优先保留 `名称/代码/动作/价格/风险/状态`。
- 当高度不足时，先压缩说明区与摘要卡，再压缩图表，最后才压缩表格高度。

### 13.4 各工作区自适应规则

#### 全局态势

- `Wide / Standard`：保留三栏布局。
- `Compact`：左栏与右栏收窄，中栏图表与机会池保持主视图。
- `Critical Compact`：右栏下沉为底部 Tab，只保留一个主图和一个主池表。

#### 机会池

- `Wide / Standard`：保留 `焦点区 + 计划区 + 策略/复盘区` 的完整层次。
- `Compact`：`题材热度`、`龙头榜`、`AI评测` 合并进二级 Tab。
- `Critical Compact`：只保留 `当前焦点 / 今日交易计划 / 执行队列 / 一键送审`。

#### 执行中控

- `Wide / Standard`：保留 `控制区 + 委托区 + 回执/复盘区`。
- `Compact`：`账户配置` 和 `运行维护` 折叠，`当前持仓` 下沉到委托区下方。
- `Critical Compact`：只保留 `执行阶段 / 委托执行台 / 当前委托详情 / 提交按钮 / 执行回执`。

#### 信号扫描

- `Wide / Standard`：保留 `扫描榜 + 观察池 + 盘中监控` 三段。
- `Compact`：`观察池` 和 `盘中监控` 进入底部切换区。
- `Critical Compact`：首屏只保留 `信号扫描榜` 与 `焦点说明区`。

#### 单票复盘

- `Wide / Standard`：图表、结论、交易记录并行。
- `Compact`：历史统计表与交易记录切为 Tab。
- `Critical Compact`：只保留 `单票速览 / 交易决策画像 / 复盘结论`，历史统计下沉。

### 13.5 表格自适应规则

表格列隐藏优先级建议如下：

- 一级保留：`名称 / 代码 / 动作 / 状态 / 价格 / 风险 / 时间`
- 二级可折叠：`主线 / 策略 / 置信度 / 热度 / 评分`
- 三级优先隐藏：`来源 / 备注 / 股票ID / 冗余解释列`

规范要求：

- 隐藏列后，表格仍需保留排序与选中能力。
- 不建议通过把所有列都变窄来保留“全列显示”。
- 所有数字列在窄屏模式下仍保持右对齐。

当前工程落地：

- 核心终端表已开始使用统一列优先级映射，不再只靠每张表各自维护一份 `compact_hidden` 名单。
- `标准` 模式保留一级 / 二级 / 三级信息；`紧凑` 模式优先隐藏三级辅助列；`盯盘` 与超窄模式进一步只保留一级核心列。
- `盯盘` 模式不仅压缩间距，也会主动切换表格短表头和列保留策略，让信息架构真正跟着终端密度变化。

### 13.6 图表自适应规则

- 主图最小高度不低于 `260px`，紧凑模式不低于 `220px`。
- 当宽度下降时，优先减少副图数量，不优先压缩主 K 线区域。
- 图例、悬浮说明、预设按钮在窄屏下允许合并到一个菜单中。
- 图表控制项应支持“标准态”和“紧凑态”两套高度。

### 13.7 组件自适应规则

- Chip 在窄屏下可从“标题 + 值”缩为“值优先”。
- Badge 文案超过 8 个汉字时必须截断，不允许顶破布局。
- 指标卡从四列降到两列时，卡宽优先增大，不允许内容挤成三行。
- 按钮组在窄屏下允许换行，但主按钮必须始终排在第一行最左或最右的固定位置。

### 13.8 落地到当前 Qt 工程的建议

当前项目已经有以下适配基础，可继续沿用并制度化：

- 已有最小窗口约束 `1200 x 760`
- 已有 `heroCompact`、`compactInfoTabs`、`QSplitter` 调优逻辑
- 已有 `_post_build_ui_tweaks()` 与 `_tune_workspace_splitters()` 的布局修正机制

建议下一步把这些散落逻辑收敛成统一规则：

- 把宽高断点抽为统一常量。
- 把各工作区的折叠行为抽为统一配置。
- 把表格列优先级抽为统一映射。
- 把 Hero、按钮、图表、表格的紧凑态样式抽为统一 Token。

## 17. 页面解耦与重构规范

除视觉规范外，后续所有 UI 改版还必须遵守工程层面的解耦规则。

核心原则：

- 一个 Toggle 对应一个明确职责，不承载多个无关功能。
- 一个页面只承载一条主链路，辅助功能默认折叠、下沉或拆出。
- 页面负责组合，不负责堆积业务逻辑。
- Builder、Refresh、Controller、Patch、Config 尽量分层。

建议将以下文档作为后续改版与重构的直接规范：

- [UI 解耦与重构规范](C:/Users/18335/Documents/New%20project/docs/UI_DECOUPLING_REFACTOR_STANDARD_2026-04-20.md)

以后凡是涉及：

- 新增 Toggle
- 页面扩容
- 工作区首屏改版
- 大块功能插入
- UI 相关重构

都优先按该规范判断是：

- 放入主链
- 下沉到辅助区
- 折叠到 Drawer / 更多菜单
- 直接拆成独立模块
### 17.1 Watch Mode Main Area Expansion

- `watch` 模式不只隐藏次级摘要层，还要把真实空间回收到主工作流区。
- `detail / paper / config` 页面在 `watch` 下需要同步重分配 `QSplitter`，让单票复盘、模拟盘分析、策略编辑器吃到更多首屏宽度。
- `board / detail / paper` 的核心文本主区在 `watch` 下要放开旧的标准态高度上限，避免已经下沉的说明层继续通过固定高度卡住主视图。
- `scanner` 页面在 `watch` 下也要把观察池 / 回测摘要分栏改成“摘要主区优先”，并同步提高扫描榜、观察池、盘中监控主表的高度预算。
- `config / auth / detail` 的主文本控制台也要跟随 `watch` 提高预算，尤其是配置帮助、配置状态、消息源状态、AI 审核状态、登录状态和单票指标摘要，避免主判断区继续被短面板节奏切碎。
- `detail / paper` 的图表与历史分析区也要进入同一套高密度规则：权益图、历史收益曲线、历史交易表、参数对比表以及历史分栏都要在 `watch` 下获得更高预算，避免主链分析区继续停留在标准态。
- `broker` 的执行分析区也要跟进：主线闸门、执行摘要、执行结果、执行复盘和执行分析分栏在 `watch` 下需要放开旧高度，并把执行分析 splitter 明确让位给主执行文本。
- `config` 页面里的多行策略编辑区也属于主链：公式权重、场景定位、空仓提示、动作模板、失败样本等表单文本区在 `watch` 下不能继续维持短卡片高度，而要按可编辑工作台的节奏抬高预算。
- `recommend` 的 review / recap 主链也要同样处理：执行分发、单票复核、队列概览、主线推演、复盘、次日计划以及 recap 分栏都要在 `watch` 下进入连续判断节奏，而不是停在标准态短面板。
- `broker` 的委托焦点与运行维护区也属于主链补充部分：委托焦点文本、运行状态、运行日志和 setup 分栏在 `watch` 下不能继续缩成窄侧栏，而要按盘中诊断工作台的节奏放宽预算。
- `recommend` 的策略细节盒子和行动卡盒子也不能例外：决策摘要、策略细节、主线推演、动作流程、优先级看板等承载判断的容器在 `watch` 下也要抬高预算，避免主链仍然像信息卡拼贴。
- `overview` 的辅助判断文本和 `broker` 的结果回放区也需要纳入同一原则：主题摘要、数据源状态、资金画像、交易决策，以及结果回放盒子、回放事件卡，在 `watch` 下都不能继续维持标准态短面板。
- `overview` 的右侧判断盒子和 `recommend` 的 recap / 消息中心容器也要同步进入 `watch` 预算：不仅内部文本，连承载这些文本的 box 本身都要从信息卡节奏切换到工作台节奏。
- `overview / recommend / broker` 的大容器本体也要遵守同一套节奏：cockpit、playbook、主线看板、策略中控、posttrade section、execution column 这类 section 不能只靠内部文本扩容，容器本身也必须在 `watch` 下放开预算。
- `drawer / stage` 级容器也属于同一层级：overview controls drawer、overview stage container、recommend controls drawer、broker setup drawer 在 `watch` 下都要按工作台预算展开，避免壳层还是标准态、内容层已经是高密度的割裂感。
- `watch` 模式下不仅要扩内容，还要压壳层留白：hero、stage hero、drawer、stage container 的 margins / spacing 需要同步收紧，否则即使预算放开，视觉重心仍会被外层 chrome 稀释。
- `workspaceHero / workspaceStageHero` 自身也要同步紧凑化：badge rail 的宽度、grid spacing 和 subtitle 占高都要在 `watch` 下更克制，避免顶部摘要带继续过宽、过高。
- 当主链已经就绪时，`watch` 首屏应优先保留 focus strip 和主视图，把页头那层重复 `statusBanner` 下沉或隐藏；否则会形成 “Hero / Status / Focus” 三层同权重提示，持续稀释主视图。
- `watch` 模式下还应自动落到最该看的子视图：机会池默认落到执行审查、交易页默认落到委托提交、扫描页优先落到盘中监控、配置页优先落到策略配置。前提是用户没有手动锁定当前 tab。
- `focus strip` 的副标题句式也需要统一成同一顺序：先回答“当前状态”，再回答“焦点”，最后回答“下一步”。不同页面可以换内容，但不应再各说各话、顺序错乱。
- 工具区 `live summary` 的 `headline / detail / meta` 也要遵守同一层级：`headline` 只回答当前状态，`detail` 只回答焦点，`meta` 只回答下一步，避免同一块里再混入平级信息。
- focus banner 也要沿用统一语义词表：可见文案优先出现“当前状态”和“下一步”，tooltip 固定回答“当前状态 / 焦点 / 下一步 / 交互”，避免不同页面再各自定义建议词和跳转提示。
- 拆页后的旧产品能力不能因为 UI 重组而“像被删掉”：战法、消息源、AI、历史战法、巡航、回封监控这类能力必须重新收束成显性入口，再决定它们在首屏还是子视图里呈现。
- 机会池这类多子视图页面，至少要保留一层“能力总览”把战法中控、策略细节、今日计划、复盘消息重新并排呈现；否则拆页后会只剩局部卡片，用户会误判成功能被删掉。
- 单票复盘也要保留一层“能力总览”把单票结论、信号与交易回放、历史战法重新摆回同一页首个主链入口；否则用户只会看到碎片化文本，不会意识到历史统计和逐笔回放还在。
- 具体业务设计、UI 布局和信息层级可以由改版负责人按规范自主决策，但前提不能变：旧功能不能丢，必须先把能力完整回补，再谈视觉收口与主链简化。
- 实验台也要保留一层“能力总览”把实验总览、持仓与交割、战法与巡航重新摆回显性主链；否则用户只会看到实验文本和零散表格，不会意识到巡航日志、战法表现和交割分析都还在。
- 涨停策略页也要保留一层“能力总览”把候选判断、回封监控、执行准备重新摆回同一条连续工作流；否则用户只会看到候选表和监控表，不会意识到打板链路已经可以直接接进交易执行。
- 扫描页也要保留一层“能力总览”把扫描候选、观察池与回测、盘中监控重新摆回显性主链；否则用户只会看到三张表拆开摆放，不会意识到观察池、回测摘要和监控联动其实还是同一条链路。
- 执行中控也要保留一层“能力总览”把执行总览、委托提交、回执复盘、接入维护重新摆回显性主链；否则用户只会看到不同 stage 分散摆放，不会意识到整条执行链路其实已经能从判断一路走到回执复盘。
- 总览也要保留一层“能力总览”把市场判断、主线龙头、消息催化、买卖决策重新摆回显性主链；否则用户只会看到大量面板和 quick action，旧能力入口仍然不够直观。
- 接入中心也要保留一层“能力总览”把接入通道、凭据校验、Bridge 环境、后续入口重新摆回显性主链；否则用户只会看到一整页表单和状态文本，不会意识到接入链路其实已经有清晰的校验和后续去向。
- 所有“能力总览”都必须共用同一套组件语义：`metric-band` 容器、统一的 capability card、统一的标题/摘要/下一步层级，以及统一的 `watch` 下沉纪律，不能每页再各自长一套。
- 所有“能力总览”的入口动作词也必须统一：同页/同工作区入口优先用“看…”，跨工作区动作才用“去…”，不再混用“打开 / 查看 / 前往”这类长短不一的文案。
- 低频入口、tooltip 和更多菜单也要服从同一套动作语言：尽量用短促的终端词，不把“打开更多 / 查看详情 / 前往某页”混成一组风格各异的次级入口。
- 确认弹窗相关提示也要沿用同一套终端语气：优先用“进入确认弹窗”“看原文”“看详情”这类短句，不再混回“打开确认弹窗”“可查看原文”这类旧式说明词。
