# 3-2. 模拟盘与通知模块 - PaperTradingNotification

## 模块概述

模拟盘与通知模块负责把交易纪律落到账本和消息里。它的目标不是多发消息，而是让用户只在关键时刻收到清晰、可复盘的动作通知。

---

## 核心优势

1. **事件驱动**
   买入、卖出、风险预警和复盘都以事件形式沉淀。

2. **双账本**
   JSON 账本便于人读，SQLite 便于统计和复盘。

3. **低噪音**
   飞书只推早评、真实模拟买入、真实模拟卖出、晚评。

4. **可追责**
   通知记录、调度运行、模拟盘闭环和收益质量都可以回看。

## 核心文件

| 文件 | 职责 |
|---|---|
| `server/firemoney_server/infrastructure/paper_store.py` | 事件驱动模拟盘账户 |

| `server/firemoney_server/application/one_to_two_notification_text.py` | 早评、买卖、晚评文案 |
| `server/firemoney_server/infrastructure/feishu_notifier.py` | 飞书 webhook/app adapter |

---

## 通知边界

| 场景 | 是否发飞书 | 原因 |
|---|---:|---|
| 早评 | 是 | 开盘前核心判断 |
| 真实模拟买入 | 是 | 账本已经写入买入事件 |
| 真实模拟卖出 | 是 | 账本已经写入卖出事件 |
| 晚评 | 是 | 收益、风险、下一步 |
| 候选扫描 | 否 | 信息噪音大 |
| 本地指挥单 | 否 | 只读参考，不代表已成交 |
| 医生检查 | 否 | 工程预检，不是交易动作 |
| 飞书测试 | 手动触发 | 只验证联通 |

## 核心流程

```text
paper-decision
  -> 只读指挥单，不改账本

watch --phase open
  -> 条件满足才写入模拟买入
  -> 买入事件符合低噪音规则才发飞书

watch --phase risk
  -> 处理持仓风险、T+1 卖出和锁盈
  -> 卖出事件符合低噪音规则才发飞书

eod
  -> 统计当天事件、闭环样本、收益和下一步
  -> 发送晚评
```
