# 框架概览 - Architecture Overview

## 模块概述

FireMoney 采用“客户端展示 + 服务端可信业务 + 共享契约 + 可复用框架层”的分层方式。当前是本地/单机可运行的模块化单体，但边界按可部署服务设计。

---

## 目录地图

```text
client/
  desktop/firemoney_client/
    cli/                 CLI 参数解析和命令分发
    presenters/          brief 和通知展示转换
    renderer.py          预览页入口渲染
    render_sections.py   页面分区渲染
    preview.py           生成本地 HTML 预览

server/firemoney_server/
  application/           每日决策、模拟盘、通知、复盘、值守编排
  domain/                主线首板评分、拦截、仓位和风控规则
  infrastructure/        行情、飞书、本地账本、配置、交易日历

shared/
  contracts/             跨客户端/服务端 DTO 和报告协议

framework/
  config/                通用配置加载
  storage/               JSON / SQLite 基础存储能力
  scheduler/             调度状态与 due window
  notification/          通知抽象模型
  http/                  未来 HTTP/RPC 边界占位
```

---

## 正确依赖方向

```text
client -> shared/contracts
client -> server application adapter
server application -> domain
server application -> infrastructure interfaces/adapters
infrastructure -> framework
shared/contracts -> no business side effects
framework -> generic primitives only
```

---

## 边界表

| 层 | 可以做 | 不可以做 |
|---|---|---|
| `framework` | 配置、存储、通知抽象、调度基础件 | 认识股票策略、A 股交易规则、FireMoney DTO |
| `shared/contracts` | 稳定报告 DTO、状态枚举、跨端字段 | 访问文件、行情、飞书或 UI |
| `domain` | 评分、拦截、仓位、风控、纯规则 | 读写账本、发通知、调用 AkShare |
| `application` | 编排用例、组合报告、调用策略和仓储 | 写页面 HTML、硬编码第三方字段 |
| `infrastructure` | AkShare、飞书、本地文件、SQLite、配置 | 决定交易规则 |
| `client` | CLI、预览页、brief 文案和用户体验 | 重新计算可信交易结论 |

## 核心服务

| 服务 | 职责 |
|---|---|
| `strategy_decision_service.py` | 决定今天主线还是空仓 |
| `paper_decision_service.py` | 生成只读模拟盘指挥单 |
| `watch_phase_service.py` | 处理 scan / auction / open / risk 阶段 |
| `paper_entry_policy.py` | 判断买点是否可执行 |
| `paper_exit_policy.py` | 判断持仓是否需要卖出 |
| `notification_orchestrator.py` | 控制飞书低噪音发送和通知审计 |
| `morning_report_service.py` | 早评候选与通知边界 |
| `end_of_day_review_service.py` | 晚评、闭环样本和下一步建议 |
| `doctor_review_service.py` | 行情、飞书、账本、调度和值守预检 |

## 坏味道

出现这些情况就应该重构：

- `framework/` import FireMoney 业务包。
- 客户端直接读 `.firemoney` 账本或 AkShare 字段。
- 一个 application service 同时写账本、发飞书、渲染 HTML。
- 策略阈值散落在多个文件，而不是由配置和领域规则集中控制。
- 生成的 HTML、截图、SQLite 或本地运行状态被提交到 Git。
