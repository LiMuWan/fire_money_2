# 项目工作原则

本项目默认遵循 `$project-principles-lead` 工作法。

## 工程原则

- 能抽象尽量抽象。
- 能复用尽量复用。
- 能一次做好就一次做好。
- 不在代码里继续堆补丁。
- 需要重构时就重构，但重构必须服务真实边界。
- 先分层，再细分功能。
- 业务和框架解耦，业务和业务之间也要解耦。
- 需求必须拆分为客户端、服务器、共享契约、文档和测试。
- 能服务器/业务层实现的可信规则，优先服务器/业务层实现。
- 每个功能完成后更新文档和 TODO。
- 使用 Git 管理，每个完整功能及时提交。

## 产品原则

- 先深挖真实需求，再设计功能。
- 用 UI 表达需求，不用页面堆功能。
- 大道至简。
- 页面简洁、主次清楚、用户体验优先。
- 只要能满足用户真实需求，不做花里胡哨的设计。
- 核心业务线明确后，只保留这条线；旧 demo、旁支入口、样例流和当前目标无关的文档都要清理。
- 当前 FireMoney 产品默认只服务主板 10cm 主线首板模拟盘验证。
- 交易相关操作必须强调状态、风险、止损、T+1 纪律、模拟盘事件和复盘。
